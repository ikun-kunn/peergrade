# PeerGrade 校选演示指南（3–5 分钟）

演示主题：**好的反馈，从一处证据开始。** 用同一案例的提交、互评和反馈三个阶段，说明如何将原文证据、结构化评价、匿名分配及教师复核串联起来。所有预置账号、作业与评分均为合成演示数据。

## 一、演示前准备

在本地 `peergrade` 目录安装依赖并构建页面，使用新的独立 SQLite 文件，避免上次演示的截止时间、已提交评价影响本次操作。以下示例为 Windows PowerShell；在已激活 Python 虚拟环境的终端运行：

```powershell
pip install -r requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build
$env:APP_ENV = 'development'
$demoStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$env:DATABASE_URL = "sqlite:///./preview-$demoStamp.db"
# 先以纯人工互评方式演示，避免无意调用现有模型配置
$env:AI_API_URL = ''
$env:AI_API_KEY = ''
$env:AI_MODEL = ''
python -m tests.seed_preview
python run_local.py --port 8000
```

浏览器访问 `http://127.0.0.1:8000/`。`seed_preview` 启动数据库迁移并生成三个不同阶段的示例，不会把测试账号加入生产数据库。`run_local.py` 只监听本机。

| 身份 | 合成账号 | 演示密码 |
|---|---|---|
| 教师（林老师） | `preview_teacher` | `preview123456` |
| 学生 | `preview_student1` 至 `preview_student5` | `preview123456` |

建议准备两个独立浏览器会话（一个教师、一个学生，例如独立隐私窗口或两个浏览器），避免同一浏览器的登录 Cookie 相互覆盖。学生登录 `preview_student1`，教师登录 `preview_teacher`。请使用合成账号，不要将真实密码或 API Key 录进视频。

三项预置任务：

| 任务 | 页面状态 | 用途 |
|---|---|---|
| 人工智能与教育：案例分析 | 提交中 | 演示学生看任务要求、在线提交作业 |
| 案例分析：互评演示 | 互评中 | 5 名学生各收到 2 个待评价任务，共 10 条分配；演示证据、评价和质量检测 |
| 案例分析：反馈演示 | 已结束/已发布 | 5 名学生各有 2 份合成评价，演示匿名反馈、证据跳转和教师统计 |

预置任务时间基于首次生成时间，后续重复运行不更新原任务截止。因此每次录制前使用新的数据库文件。不要为缩短演示而绕过真实截止时间：已进入互评及已结束的示例是预先构造的演示夹具。

## 二、AI 演示方式（二选一）

如果已经获得真实模型 API 的使用授权与密钥，先执行合成样例验收，例如：

```powershell
python -m tests.check_quality_model --deepseek --out quality-check-demo.json
```

输出文件须使用未存在的文件名；打开结果查看模型返回的版本、结构及耗时，并由人工核对结果。真实 DeepSeek 演示时在同一数据库环境使用 `python run_local.py --deepseek --port 8000`，密钥在终端隐藏输入，不写入项目或镜头。遇到模型连接失败、无效输出或超时，照常使用保存草稿、人工修改和提交路径。

可选 `--pricing` 记录来自供应商的、由运营者核验的单价版本及估计费用，字段格式见 README。用量或价格未知时报告相应缺失原因，不填零。上线前将模型输出与人工判断分别留档；没有 API Key 时只运行合成替代响应或无模型路径，不生成冒充真实模型的成本/效果报告。

如果没有真实模型密钥：可以直接演示人工匿名互评，点击检测表明暂不可用后仍可正常提交；也可以单独展示**本地模拟 UI**，明确在视频画面和讲解中注明「模拟响应，不是模型效果证据」。模拟服务使用固定的 `preview_ui.db`：若已有旧演示数据，请先保留原数据库，另用干净的项目演示副本运行下列命令，避免覆盖或删除既有记录。

```powershell
$env:APP_ENV = 'development'
$env:DATABASE_URL = 'sqlite:///./preview_ui.db'
python -m tests.seed_preview
python -m tests.preview_mock
```

浏览器访问 `http://127.0.0.1:8766/`。该脚本固定返回 LOW 及「补充原文依据」建议，专门测试界面和降级体验，不随评价质量真实变化。不能把固定值说成模型智能判断；不能凭模拟输出声称改进有效或用它制作实验数据，更不能部署到公网。

## 三、建议录屏分镜（约 4 分 20 秒）

| 时间 | 画面与动作 | 建议讲解 |
|---|---|---|
| 0:00–0:30 | 登录页、学生「我的学习任务」 | 课程互评经常只有笼统评价。PeerGrade 让评价可以回到原文，说明理由并给出行动建议。为在短时间完整展示，我们使用三个已经准备好的合成任务阶段。 |
| 0:30–1:10 | 学生打开「人工智能与教育：案例分析」，查看作业要求与三个评分维度；输入短文本，点击「保存文字作业」。切换教师「教学工作台」，简要查看同任务。 | 教师预设量规与参与名单；学生只看到自己参与的任务。支持在线文字与文字型 PDF，互评启动后冻结作业正文，保留后续证据定位的版本。 |
| 1:10–1:50 | 教师打开「案例分析：互评演示」→「查看教师看板」；显示 5/5 已交和 10 条互评任务；再回学生「我的互评」，打开同名任务的一条待评价记录。 | 系统以有效提交者为随机环，每人评两份、每份获两位不同评审者，避免自评与重复分配。学生只读匿名作品和编号；分配种子及进度由教师核查。该例是预置互评阶段，现场不等待截止。 |
| 1:50–2:50 | 左侧选中「人工智能可以辅助学习。」附近一段原文，点「＋ 添加选中内容为证据」。为三个维度填写适当分数和三段评价：「题目推荐的作用说明具体」「缺少试点数据，无法判断实际成效」「建议补充试点前后错题率及样本人数」。点「保存草稿」，返回任务列表重新打开，检查文字和证据恢复。 | 证据并非复制一段话：还保存其位置及作业版本摘要，服务器根据当前正文校验，刷新后仍能定位。草稿允许学生分次完成，不会提前变为正式评价。 |
| 2:50–3:25 | 有真实模型时点击「✳ 检测反馈质量」，显示三维结果和建议，按提示自主修改评语后提交；无真实模型时按上一节方式展示不可用继续提交，或明确标识固定模拟提示后提交。 | AI 检查具体性、依据性、可操作性，不给作业评分，不自动替学生改写。反馈有参考价值，但实际效果必须经学生评价前后对比和人工盲评。无模型时系统仍可运行。 |
| 3:25–4:05 | 学生返回主页，打开「案例分析：反馈演示」→「查看收到的反馈」。展示两个匿名评审的总分、三维平均及评语，分别点击两个相同文字的证据跳转按钮，查看不同原文位置。教师切换同任务看板，显示 5/5 提交、10/10 完成以及完整评分平均 11/15。 | 同样的引文可能出现多次，系统仍可通过起止位置精确跳到对应原文。教师看到整体进度、评分、分歧及检测记录，发布由教师决定。演示分数仅为合成示例。 |
| 4:05–4:20 | 展示技术设计图或实验方案标题，回到产品首页。 | 作品的重点是可追溯、可操作的学习反馈。真实模型联调、参与者的人工盲评和目标公网部署将在相应资源和授权具备后按验收清单完成，不用演示数据代替真实研究结果。 |

时间紧张时省略创建任务或保存草稿后的重新打开过程，但应保留**证据选择、匿名互评、证据跳回原文及教师看板**四段，这是作品的核心差异点。模型等待超过可用录制时间可提前使用预录的真实合成样例联调结果，清楚注明测试时间与模型版本；不能把模拟结果伪装成现场真实响应。

## 四、现场检查与交付边界

- 录制前验证两种身份都能正常登录、任务处于预期阶段，文字作业、证据选择和已发布反馈两个跳转都可展示。
- 确认浏览器显示实际构建的前端，文本和按钮没有被缩放截断。教师看板中的身份和评分均为合成数据，切勿使用真实课程作业录屏。
- 若需要额外演示真正从「开启匿名互评」到「发布反馈并结束任务」的全过程，可提前创建真实合成任务、至少三名学生完成提交；等待提交截止后再启动，完成所有互评或等待互评截止后发布。不可把预置的 `REVIEWING`、`CLOSED` 数据声称为现场创建结果。
- 本指南是可操作的分镜和演示手册，不是已录制的视频，也不是公网发布或实验报告。正式提交仍需准备可访问网址、Git 仓库、[技术设计](technical-design.md)、实际测试结果、经授权的真实模型结果、[真实参与者实验](experiment.md)、录制成片及答辩 PPT；完整门槛见 [发布核验清单](release-checklist.md)。
