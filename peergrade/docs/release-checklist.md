# 发布前核验清单

本清单记录软件发布门槛、已有历史证据及待执行事项。下列核验项针对**实际待发布提交和目标运行环境**；未完成同等范围的复验不得勾选。开发机上的合成样例、模拟响应和端口预览并不证明正式部署或真实实验完成。

## 功能与数据

- [ ] 注册新学生，检查密码确认、重名提示、返回登录；登录后确认未被教师选入时没有课程任务，选入后才出现任务。
- [ ] 验证提交不足三人时可延期补交、教师可见未交名单，互评窗口过期且未启动时可结束任务；过期评价不计入学生待办且不可提交。
- [ ] 执行 `npm run build` 后通过 FastAPI 打开应用，确保实际提供最新构建；发布平台排除 `dist` 时执行 `npm run build:publish` 并核对 `webroot` 版本。
- [ ] 用非真实个人数据完成教师建任务、至少三名学生提交、启动互评、提交评价、结束任务、作者查看反馈。
- [ ] 复测文本、文字型 PDF、空白或扫描型 PDF、超过页数和大小限制的文件；确认原始 PDF 不能由评审者下载。
- [ ] 对 3、5、10、30 名提交者检查每人两份、每份两人、无自评和无重复；验证重复启动及分配事务。
- [ ] 在含中英文、换行、表情的正文中选取证据，刷新后定位；确认错误的证据位置、内容摘要或跨作业证据被拒绝。
- [ ] 运行 `npm --prefix frontend test`，检查相同引文能否定位到各自位置、保存草稿遇到 409 时能否保留本地编辑，以及教师发布入口是否更新。
- [ ] 确认只有参与学生与所属教师能查看任务，学生不能读取分配范围以外的作业及其他人的反馈；教师能查看完整记录。
- [ ] 检查零份、一份和两份互评时的反馈、平均分与高分歧统计；确认关闭后不能新增评价。

## AI 与实验

- [ ] 确认可用模型服务及数据处理授权，配置服务端密钥并测试低、中、高质量评价。记录模型版本、测试输入和人工判断，不把模拟响应作为真实模型结果。
- [ ] 运行 `python -m tests.check_quality_model --out quality-check.json`（如使用已获授权的 DeepSeek 官方配置，可加 `--deepseek`），记录四组合成样例的输出和耗时。核对请求模型与供应商返回版本，填写每组 `human_assessment`；样例的 `expected_level` 为预设等级。
- [ ] 验收超时、无效结构、并发、次数限制、检测中/成功/失败计数及质量分统计。核对调用次数；确认失败或达到上限仍可提交评价，AI 分数不计入作品成绩。
- [ ] 按[实验方案](experiment.md)组织真实自愿参与者，独立收集前后评价并进行两人人工盲评；记录样本量、缺失数据、分数变化和研究局限。真实数据不得提交至代码仓库。

## 数据迁移与生产环境

- [ ] 确认 GitHub Actions 的 PeerGrade verification 对待发布提交执行，前端构建、SQLite 和 PostgreSQL 16 检查均通过。
- [ ] 确认待发布版本的 Alembic 版本链：`0001_initial` → `0002_review_drafts`。在专用测试库用 `python manage.py db-status` 检查版本，运行 `python manage.py upgrade-db` 并再次校验；验证空库初始化、重复升级、已知未版本化旧库接管、错误结构拒绝升级及事务回滚。
- [ ] 将 `PEERGRADE_TEST_POSTGRES_URL` 指向专用测试库，在目标 PostgreSQL 版本运行 `python -m unittest discover -s tests -v` 和 `python -m tests.check_release`。记录核心流程、并发、重复提交、权限及 10 个演示账号常用接口耗时（每请求目标 2 秒内）。
- [ ] 在目标 PostgreSQL 测试库执行 `python -m tests.check_restore`。用真实备份/恢复工具和合成数据验证恢复至新库，并核对同一任务、两份已发布反馈及对应原文证据。
- [ ] 在目标环境验证 `docker compose config --quiet`、完整镜像构建、`init` 版本升级成功、`web` 健康检查及 Caddy 启动依赖；数据库未升级至当前版本时 `/healthz` 应不可用。
- [ ] 核对账号管理、密钥管理、数据处理知情说明、日志和个人数据保存期限，并确认备份安全及恢复方案。真实数据不得放在静态网页目录或代码仓库。
- [ ] 实测代理可信来源、客户端地址、请求体限制、登录限流、HTTPS 证书、安全 Cookie 和跨来源保护。可在专用测试库用 `tests.check_production`、`tests.check_proxy --caddy /path/to/caddy` 及 `--browser` 先做本机演练；目标服务器必须再验证实际网络路径。
- [ ] 在可供评审访问的公开网址上，用教师和学生账号完成业务闭环；检查 PC 与手机浏览器、目标负载、健康检查和恢复流程。
- [ ] 根据学校当届竞赛通知核对部署、参赛材料、团队人数及 AI 工具披露要求，并补齐最终技术报告、ER 图、架构图、算法与 AI 输出说明、实测实验报告、演示说明、3—5 分钟演示视频和答辩 PPT。

## 历史本地证据

以下是 2026-11-19 已提交基线文档内的历史验收记录，用于保留过去测试覆盖与运行环境的信息；当前代码及部署包需重新验证，不能仅凭这段历史记录勾选以上门槛。

### 本地功能回归

- V2.1 基线记录 Python 3.14 + SQLite 的 78 项后端、Vue 6 项组件测试及 `build:publish` 通过，包括学生注册、延期、未启动结案、互评过期及前端两套构建一致性。
- 记录本地 Edge 390 × 844 手机视口注册密码确认、新账号登录且无课程任务、1280 × 800 桌面视口教师学生名单、延期及未开展互评任务结案；本地合成作业证据可选择、提交、刷新回显。
- 10 个合成账号的进程内并发检查记录登录最大 405.5 ms，其余接口最大 206.3 ms；SQLite 恢复演练核对任务、两份评价和两处证据。该结果不是公网负载测试。

### PostgreSQL、恢复及生产配置

- 基线随后记录 Windows 本地隔离 PostgreSQL 16.15、Python 3.14、SQLAlchemy 2.1.9 的 82 项后端测试通过，SQLite 与 Vue 6 项通过；本地另有 PostgreSQL 16.16 和 SQLite 的 13 项早期核心回归记录，两组记录来自不同代码及环境。
- 记录 PostgreSQL 中使用 10 个合成账号进行 3 轮读取，登录最大 648.8 ms，其他接口最大 197.7 ms；使用 `pg_dump` / `pg_restore` 16.16 创建 32,075 字节合成数据归档，恢复后核对任务、两份反馈及两条证据。
- `tests.check_production` 在本地 PostgreSQL 使用模拟 HTTPS 来源的历史结果覆盖健康检查、学生注册、登录、权限初始状态、退出和 `Secure`/`HttpOnly`/`SameSite=Strict` 这些会话属性。
- 记录了 CI 配置及双人盲评工具合成数据测试，没有目标服务器或真实参与者验收。

### 本地 HTTPS、AI 配置与浏览器

- 基线记录 DeepSeek 本地隐藏输入和合成质量报告入口、JSON 输出及关闭思考模式的模拟接口测试；未提供真实模型密钥，未发生真实模型调用。
- 在本机隔离 Caddy 2.11.9 + PostgreSQL 16.15 + FastAPI 实际 HTTPS 测试中，HTTP 客户端验证临时 CA 与主机名。服务只监听回环地址，不安装系统证书或数据库服务。
- 记录三名合成学生通过 HTTP 注册、提交、完成六条匿名互评、草稿保存恢复、无 AI 时正常提交、发布后检查三份反馈及六处锚点；PDF 提取和大小限制、代理请求体限制均有本地覆盖。Edge 的 390 × 844 和 1280 × 800 视口验证了反馈证据跳转、教师 3/3 提交及 6/6 互评看板。
- 基线追加记录全量 SQLite/PostgreSQL 回归各 83 项及 Vue 6 项；并发、恢复及本地生产会话检查通过。以上历史验证尚不等同当前待发布代码、Docker Compose 实机部署或真实公网访问的证明。

## 未完成的外部验收

尚需目标服务器及域名、DNS 和受信任的 HTTPS 证书；当前没有已验证的公网正式部署。真实模型联调及人工判断需要取得模型服务授权和密钥；真实学生实验需要征得参与者知情同意后实施。参赛材料必须依据最终实测结果和当届竞赛通知整理。没有这些证据时，不得标称正式发布或对教育效果作已验证声明。
