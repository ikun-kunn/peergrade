# 发布前核验清单

本清单用于记录上线门槛，不代表已经完成验收。应对准备部署的实际版本和目标环境逐项复测并留存结果。

## 功能与数据

- [ ] 注册新学生，检查密码确认、重名提示、返回登录；登录后确认未被教师选入时没有课程任务，选入后才出现任务。
- [ ] 验证提交不足三人时可延期补交、教师可见未交名单，互评窗口过期且未启动时可结束任务；过期评价不计入学生待办且不可提交。
- [ ] 执行 `npm run build` 后通过 FastAPI 打开应用，确保实际提供最新构建；发布平台排除 `dist` 时执行 `npm run build:publish` 并核对 `webroot` 版本。
- [ ] 用非真实个人数据完成教师建任务、至少三名学生提交、启动互评、提交评价、结束任务、作者查看反馈。
- [ ] 复测文本、文字型 PDF、空白或扫描型 PDF、超过页数和大小限制的文件；确认原始 PDF 不能由评审者下载。
- [ ] 对 3、5、10、30 名提交者检查每人两份、每份两人、无自评和无重复；验证重复启动及分配事务。
- [ ] 在含中英文、换行、表情的正文中选取证据，刷新后定位；确认伪造位置、内容摘要或跨作业证据被拒绝。
- [ ] 在项目目录运行 `npm --prefix frontend test`，检查相同引文能否定位到各自位置、保存草稿遇到 409 时能否保留本地编辑，以及教师发布入口是否更新。
- [ ] 确认只有参与学生与所属教师能查看任务，学生不能获取非自己评审范围的作业及其他人的反馈；教师能查看完整记录。
- [ ] 检查零份、一份和两份互评时的反馈、平均分与高分歧统计；确认关闭后不能新增评价。

## AI 与实验

- [ ] 确认可用的模型服务及数据处理授权，配置服务端密钥并测试低、中、高质量评价。记录模型版本、测试输入和人工判断，不把模拟响应作为真实模型结果。
- [ ] 在项目目录运行 `python -m tests.check_quality_model --out quality-check.json`，记录四组合成样例的输出和耗时。核对请求模型与供应商返回的版本，填写每组 `human_assessment`。样例的 `expected_level` 是人工设计的预期等级。
- [ ] 实测超时、无效结构、并发和次数限制。核对实际模型调用数，以及看板的检测中、成功与失败计数。验证失败或达到上限时仍可提交评价。
- [ ] 按 [实验方案](experiment.md) 组织真实自愿参与者和人工盲评，记录样本数量、缺失数据和结果局限。

## 生产环境

- [ ] 检查 GitHub Actions 的 PeerGrade verification 运行结果，确认 Vue、SQLite 和 PostgreSQL 16 检查均通过。
- [ ] 将 `PEERGRADE_TEST_POSTGRES_URL` 指向专用测试库，在目标 PostgreSQL 版本上运行 `python -m unittest discover -s tests -v` 和 `python -m tests.check_release`。记录核心流程、并发启动、重复提交、权限测试及 10 账号接口耗时。
- [ ] 在目标 PostgreSQL 测试库执行 `python -m tests.check_restore`。用合成数据验证备份可恢复到新库，并核对同一任务、两份已发布反馈及对应原文证据。
- [ ] 检查数据库迁移方案、账号管理、密钥管理、日志及个人数据保留策略。
- [ ] 实测代理可信来源、客户端地址、请求体限制、登录限流、HTTPS 证书、安全 Cookie 和跨来源保护。
- [ ] 在公开网址上用教师和学生账号完成验收；检查 PC 与手机浏览器、负载和恢复流程。
- [ ] 根据学校当届竞赛通知核对部署、参赛材料、团队人数及 AI 工具披露要求。

## 当前已知证据

本地自动化覆盖双人分配、30 人分配、并发重复请求、数据库关联完整性、权限、PDF 提取、AI 模拟输出和超时、反馈计算与高分歧提示。前端曾以本地合成数据验证证据选择、提交和回显。具体数据库版本和运行环境见下方记录，真实模型、目标服务器和真实用户实验仍需独立验收。

### 2026-11-19 · V2.1 本地回归

- Python 3.14 + SQLite：78 项后端测试通过（含注册、延期、未启动结案和互评过期）。
- Vue 组件测试：6 项通过（新增注册、教师延期及结案、过期评价待办统计）；`build:publish` 成功，两个前端构建入口及资源版本一致。
- 本地 Edge 浏览器：390 × 844 移动窗口完成注册密码确认、注册后返回登录并登录、新账号无任务；1280 × 800 桌面窗口确认新学生出现在教师名单、延期补交、结束未开展互评的任务。
- 10 个合成账号的应用进程内并发检查通过，登录最大耗时 405.5 ms，其余接口最大耗时 206.3 ms，均低于 2 s 目标。这不是公网负载测试。
- SQLite 恢复演练通过，恢复任务、2 份已发布互评与 2 条原文证据锚点。

以上均使用临时 SQLite 数据与合成账号，未请求外部模型；PostgreSQL、真实 AI、目标服务器与真实参与者实验仍需按清单验收。

### 2026-11-19 · PostgreSQL、恢复与生产配置追加验收

- Windows 本地隔离 PostgreSQL 16.15（便携测试实例，运行后停止）、Python 3.14、SQLAlchemy 2.1.9：82 项全部通过。实测发现原登录/注册限流 SQL 的 `window` 保留字与新版 SQLAlchemy 向客户端传递适配器对象的问题，修复后复测通过。
- 同版本 SQLite 回归 82 项、备份恢复及 Vue 组件测试 6 项复测全部通过。
- PostgreSQL 10 个合成账号、3 轮应用进程内并发读取通过；登录最大 648.8 ms，其他接口最大 197.7 ms（目标 < 2 s）。该结果不代表公网负载性能。
- 真实 `pg_dump` / `pg_restore` 16.16 恢复演练通过（32,075 字节测试归档），在新数据库核验任务、2 份已发布互评及 2 条证据锚点，恢复结果与源库一致。
- `tests.check_production` 在 PostgreSQL 下用模拟 HTTPS 来源通过，覆盖健康检查、学生注册、登录、权限初始状态、退出与 Secure / HttpOnly / SameSite=Strict Cookie；没有实际 TLS、反向代理或公网访问。
- 双人盲评工具与采集模板已准备，通过合成数据测试，包含匿名随机编号、同意和缺失记录处理、双人评分汇总与评分者一致度；没有真实参与者或实验结论。
- CI 配置已包含两种数据库的并发检查和 PostgreSQL 生产配置检查；远程 GitHub Actions 的新提交运行结果尚未核验。

上述是本地版本证据，目标服务器（Docker/Caddy、DNS/TLS、数据库及备份）、真实 AI 模型联调和真实学生实验仍未验收。部署操作见 [部署手册](deployment-runbook.md)。
